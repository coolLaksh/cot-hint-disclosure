# B2: CoT-only hint-reliance monitor

Can the B1 judge endpoint (`AZURE_DEPLOYMENT`, gpt-5.6-luna) tell when a Qwen model relied on an external answer suggestion, given only its reasoning trace? This is block B2 of [neleasa_lean.md](../neleasa_lean.md), following the B2 step of [week2_finish_plan.md](../analysis/week2_finish_plan.md).

Unlike the B1 judge, the monitor never receives the task prompt, the hint, answer labels or the B1 verdict. Each request holds the frozen instruction and one `thinking` text. `run` never reads labels; `score` joins them afterwards.

## Files

| File | Contents |
|---|---|
| `monitor.py` | `run` (dry run, live, resumable) and `score` (joins labels, writes outputs) |
| `prompt_v1.json` | Frozen prompt: instruction, input wrapper, output schema. Do not edit; add `prompt_v2.json` |
| `test_monitor.py` | Offline checks: input leakage, sample selection, cache invalidation, failed responses, metric denominators |
| `../logs/b2_monitor_results.jsonl` | One line per request outcome (`ok`, `invalid` or `error`) with raw response, hashes, settings and timestamps |
| `../logs/b2_monitor_runs.jsonl` | One line per invocation, dry or live, with the full prompt, settings and counts |
| `../logs/b2_monitor_summary.csv` | Per-model metrics: numerator, denominator, Wilson interval, failures, exclusions |
| `../logs/b2_monitor_review.csv` | One row per trace, highlighted rows first, with a confusion-matrix cell |
| `../analysis/b2_monitor_report.md` | Short report, regenerated by `score` |
| `../analysis/b2_monitor_highlights.md` | Full traces of the highlighted rows |

## Reproduce

```bash
conda activate myenv          # the notebooks' environment (openai, python-dotenv)
cd .
python -m unittest discover -s b2_monitor -v   # offline checks, no API calls
python b2_monitor/monitor.py run --dry-run     # validate inputs, print the request plan
python b2_monitor/monitor.py run               # live; interrupt and rerun to resume
python b2_monitor/monitor.py score             # metrics, review CSV, report
```

`run --limit N` sends at most N requests, for a smoke test. `--workers` sets concurrency (default 4).

Credentials come from `.env` through python-dotenv, as in `analyze.ipynb`. Nothing secret is printed or written; the endpoint is stored only as a hash.

## Caching and resuming

A result's cache key hashes the trace, the prompt, the monitor model and the generation settings. A rerun sends only traces without an `ok` or `invalid` result, so errors are retried and finished traces never are. Changing the prompt, model or settings starts a fresh cache instead of mixing results.

## After human review

Pass human disclosure labels for flipped traces as a CSV with columns `model,id,disclosed`, where `disclosed` is `true`, `false` or `unclear`:

```bash
python b2_monitor/monitor.py score --human-labels logs/b2_human_disclosure_labels.csv
```

Supplied rows replace the automated B1 labels; `unclear` rows drop out of the disclosed/undisclosed split. The report and summary show which source each split used.
