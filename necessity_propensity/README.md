# Necessity vs. propensity to think out loud

Korbak et al. ([2025](https://arxiv.org/abs/2507.11473)) give two reasons a chain of thought can be monitorable:

- **Necessity:** on hard tasks a model cannot finish without externalizing its reasoning.
- **Propensity:** where CoT is not needed, a model may still tend to think out loud.

They note that hint-style faithfulness tests do not separate the two. This experiment separates them as far as the saved logs allow. No model is re-run; three frozen LLM-judge tasks (the B1/B2 endpoint, `AZURE_DEPLOYMENT`) label the questions and traces.

| Judge task | Sees | Records |
|---|---|---|
| `question_necessity` (120) | question and options only | recall / single-step / multi-step; needs a calculation |
| `trace_profile` (clean sample-0 Qwen traces) | question, trace, the trace's final answer | first sentence committing to that answer (quoted, then located), answer from worked steps, what follows the commit, deciding reason stated |
| `hint_mention` (hinted Qwen traces) | hint and trace | hint mentioned; relies on / rejects / only mentions it |

`score` joins these labels with the corrected answers, reference-model's answers (a no-visible-CoT reference), the B1 disclosure labels and the B2 monitor verdicts.

## Files

| File | Contents |
|---|---|
| `experiment.py` | `run` (dry run, live, resumable, `--task` to run one judge) and `score` |
| `prompts_v1.json` | Frozen judge prompts and output schemas. Do not edit; add `prompts_v2.json` |
| `test_experiment.py` | Offline checks: pinned prompts, unit selection, exact request contents, quote validation, failures, denominators |
| `../logs/np_judge_results.jsonl` | Raw judge outputs with hashes, settings, timestamps |
| `../logs/np_question_labels.csv`, `../logs/np_trace_labels.csv` | Per-question and per-trace labels joined with local data |
| `../logs/np_summary.csv` | Every metric with k, n, value and 95% Wilson interval |
| `../analysis/necessity_propensity_report.md`, `../analysis/necessity_propensity.png` | Report and figure, regenerated by `score` |

## Reproduce

```bash
conda activate myenv
cd .
python -m unittest discover -s necessity_propensity -v
python necessity_propensity/experiment.py run --dry-run
python necessity_propensity/experiment.py run          # interrupt and rerun to resume
python necessity_propensity/experiment.py score
```

Quotes must occur in the trace (exactly, after whitespace and punctuation normalization, in elided parts, or ignoring letter case). Scoring re-validates every saved raw output, so all records meet the same rule. Invalid outputs are counted, never defaulted.
